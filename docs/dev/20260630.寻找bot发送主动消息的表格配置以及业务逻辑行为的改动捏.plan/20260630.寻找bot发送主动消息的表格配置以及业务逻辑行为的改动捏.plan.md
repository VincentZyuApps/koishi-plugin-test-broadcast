# 20260630 寻找 Bot 发送主动消息的表格配置与行为改动计划

## 配置项

统一新增布尔配置项：`useFirstBotWhenSelfIdEmpty`。

含义：当目标配置没有填写 `selfId` 时，是否只使用第一个匹配 `platform` 的 Bot。

`true`：只使用第一个匹配 Bot；如果发送失败，可按插件语义决定是否继续尝试下一个。

`false`：对所有匹配 `platform` 的 Bot 都尝试发送。

## 插件默认值

`test-broadcast` 默认 `false`。

原因：这是主动消息测试插件，遍历所有同平台 Bot 更适合验证多个 Bot 的发送能力。

`git-repo-monitor` 默认 `true`。

原因：仓库更新通知不应默认重复发送到同一频道。

实现上建议“逐个尝试，首个成功即停止”，比直接固定 `bots[0]` 更稳。

`mclistener-ws-client` 默认 `true`。

原因：统一默认行为为 `selfId` 空时只用一个 Bot，避免多 Bot 环境下重复转发。

注意：这个默认值会改变它目前“发送给所有同平台 Bot”的历史行为，需要在更新说明中写清楚。

## 不纳入本轮

`music-link-vincentzyu-fork` 暂不做全局遍历。

它是被动命令场景，应该优先使用触发当前会话的 `session.onebot/session.bot`。

如需增强，只做当前会话 Bot 的兜底查找，不遍历全部同平台 Bot。

## 后续实施顺序

先改 `test-broadcast`，验证 `selfId` 为空时的多 Bot 发送和结果汇总。

再改 `git-repo-monitor`，实现 `true` 时首个成功即停止，`false` 时全部发送。

最后改 `mclistener-ws-client`，在现有 `resolveBots()` 基础上按配置裁剪结果。
