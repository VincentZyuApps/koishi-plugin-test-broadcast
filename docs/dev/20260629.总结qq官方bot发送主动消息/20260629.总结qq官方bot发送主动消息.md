## 核心结论

QQ 官方 Bot 主动消息分两类目标：

1. QQ 群 / C2C 单聊，也就是 Koishi 里的 `platform=qq`
   - 群消息接口：`POST https://api.sgroup.qq.com/v2/groups/{group_openid}/messages`
   - 单聊接口：`POST https://api.sgroup.qq.com/v2/users/{openid}/messages`

2. QQ 频道，也就是 Koishi 里的 `platform=qqguild`
   - 子频道接口：`POST https://api.sgroup.qq.com/channels/{channel_id}/messages`
   - 频道私信接口：`POST https://api.sgroup.qq.com/dms/{guild_id}/messages`

普通 QQ 群主动消息用的是 `group_openid`，不是传统 QQ 群号。普通 C2C 私聊用的是用户 `openid`，也不是 QQ 号。

## AccessToken 获取

```bash
curl -X POST "https://bots.qq.com/app/getAppAccessToken" ^
  -H "Content-Type: application/json" ^
  -d "{\"appId\":\"你的AppID\",\"clientSecret\":\"你的Secret\"}"
```

返回示例：

```json
{
  "access_token": "ACCESS_TOKEN",
  "expires_in": 7200
}
```

后续请求统一使用：

```http
Authorization: QQBot ACCESS_TOKEN
Content-Type: application/json
```

## msg_id / msg_seq 的区别

源码里被动回复会带：

- `msg_id`
- `msg_seq`
- `event_id`

这些主要用于回复用户刚发来的消息，或处理平台要求的消息序号。

主动消息不一定需要这些字段。`openclaw-qqbot` 的 `sendProactiveGroupMessage()` / `sendProactiveC2CMessage()` 主动发送时只构造：

```json
{
  "content": "文本",
  "msg_type": 0
}
```

或：

```json
{
  "markdown": {
    "content": "Markdown 内容"
  },
  "msg_type": 2
}
```

## 常见坑

### 1. group_openid 不是 QQ 群号

QQ 官方 Bot 的普通群接口：

```http
POST /v2/groups/{group_openid}/messages
```

这里要填群 openid。不能填 OneBot 使用的真实 QQ 群号。

`test-broadcast/src/bot.ts` 里也有校验：如果 `platform=onebot` 却填了 32 位 QQ 官方 openid，会提示目标不合法。

### 2. user openid 不是 QQ 号

C2C 主动私聊：

```http
POST /v2/users/{openid}/messages
```

这里要填用户 openid，不是 QQ 号。

### 3. qq 和 qqguild 不要混用

- `platform=qq`：普通 QQ 群 / C2C，使用 `/v2/groups` 和 `/v2/users`
- `platform=qqguild`：QQ 频道，使用 `/channels` 和 `/dms`

`test-broadcast/src/bot.ts` 中也有校验：如果 `platform=qqguild` 但 `channelId` 看起来像 QQ 群 openid，会提示应该填写真实频道 ID。

### 4. Markdown 能否发送取决于平台能力和账号权限

adapter 支持：

- `h('markdown', ...)`
- `h('qq:rawmarkdown', ...)`
- `h('qq:rawmarkdown-without-keyboard', ...)`
- `bot.internal.sendMessage(..., { msg_type: 2, markdown: { content } })`

但最终是否能成功，仍受 QQ 官方 Bot 权限、审核、灰度能力影响。

## 推荐落地方式

在 Koishi 插件内，优先用：

```ts
await bot.sendMessage(groupOpenid, content)
```

如果要发 QQ 官方 Markdown，用：

```ts
await bot.sendMessage(groupOpenid, h('qq:rawmarkdown-without-keyboard', {
  content,
}))
```

如果 Koishi 编码器不满足需求，再 fallback 到：

```ts
await bot.internal.sendMessage(groupOpenid, {
  msg_type: 2,
  markdown: { content },
})
```

如果完全脱离 Koishi，直接用 curl / Python 调官方 API 即可：

```http
POST /v2/groups/{group_openid}/messages
Authorization: QQBot ACCESS_TOKEN
```
